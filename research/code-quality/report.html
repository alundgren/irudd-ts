Clone detection catches copies and incidental similarity

The reference detector caught the 45-line agent-style copy at 0.907. It also scored unrelated behavior and deliberate boilerplate at 1.0. The short clone with a guard and an extra call scored 0.700, below its default 0.82 threshold.

Values use the reference normalization with one designated pair per authored case. Repeated and weighted fingerprints are experimental comparisons, not the reference CLI's default. The weighted measure counts overlapping subtrees; this trial does not establish a better universal metric.

Preserving property names reduced the unrelated pair from 1.0 to 0.273 in the independent TypeScript prototype. It also reduced the copied pair to 0.738 with sets, while counted fingerprints brought it to 0.843. Property preservation trades false positives for missed copies.

The selected T3 corpus contained ten files and 2,126 source lines. The reference detector considered 82 eligible functions, excluded 29 smaller candidates, and reported no pair at 0.82. jscpd also reported no real-source clone. On the authored controls, jscpd found two repeated baseline fragments across cases, but missed all six designated pairs.

Malformed TypeScript was a practical reliability failure. The reference CLI exited successfully with no candidates; the independent prototype preserved a parse diagnostic and reported incomplete analysis.

Survivors identify specific behavior the tests miss

The weak authored suite passed its baseline. Of six reference survivors, five exposed the intended missing assertions and one was equivalent under the integer-balance contract. After behavior-focused corrections, only the equivalent mutation survived. This constructed outcome cannot estimate the useful-survivor fraction in a real repository.

In the copied T3 calendar helper, the reference found a millisecond mutation that the existing tests did not distinguish:

// Original
next.setHours(selected.getHours(), selected.getMinutes(), 0, 0);
// Surviving mutation
next.setHours(selected.getHours(), selected.getMinutes(), 0, 1);

A demonstration assertion kills this mutation. First confirm whether minute precision is part of the intended contract. A survivor identifies unconstrained behavior; it does not establish a production defect. Stryker killed its five generated mutations on this reduction and did not generate the numeric mutation.

The reference cache retained killed results after test-only, configuration, helper, dependency-behavior, and failing-baseline changes. Those differential runs skipped the baseline and test command. Forced runs revealed survivors or the broken baseline. Stryker re-evaluated the test-only edit, but reused a killed arithmetic mutant after an imported-helper edit until forced to rerun. That matches its documented incremental limits.

Execution reporting matters as much as survivor reporting. The reference labels every nonzero test-command exit and timeout as killed. Our corrected observer distinguishes assertion-only failures from suite, hook, runtime, unhandled, and command errors, while retaining the original upstream status.

Choose the execution tool separately from the review signal

Structural duplicate detection

Keep the small TypeScript prototype for further review experiments. It reports both property-erasing and property-preserving measures, parse failures, excluded functions, and source locations. Use jscpd alongside it when unchanged text fragments matter.

The reference normalization demonstrates the copy/paste idea well. Its successful exit on malformed source needs a correction before its output can establish complete analysis. The author invites agents to customize the tools or write alternatives, which fits this experimental use.

Mutation testing

Use Stryker as the TypeScript execution backend for further experiments, with conservative cache invalidation or forced bounded reruns when helpers, configuration, dependencies, or environment change. Keep operator coverage visible: the reference numeric operator uncovered a useful specification question here. Export survivor locations and expressions directly to the reviewer.

Next experiments

  • Run clone detection on changed functions against selected existing code, then ask a reviewer to classify candidates before suggesting any abstraction.
  • Run bounded mutation trials on changed behavior and show survivors with their specification, original expression, replacement, and test command.
  • Compare an agent review with and without this evidence on the same change. Record the concrete mistakes found and misleading suggestions produced.
  • Expand the real-code corpus before drawing conclusions about frequency, useful-survivor percentages, or total application cost.
