Architecture rules over one shared project graph

Archguard is a Rust CLI with native rules and Rust or TypeScript plugins. It resolves source dependencies once, then gives each rule the same project facts. The completed experiments distinguish graph policy failures from runtime defects that this tool cannot establish.

What plugins receive

Eleven rule kinds support 25 default T3 policy entries, with separate iOS/Android cycle profiles and clearly labeled historical or experimental profiles. Policies cover package directions, service namespace imports, public entries, service identifiers and imported runtime calls. A transitive call check means module reachability; it does not prove execution.

Oxlint already supplies native module-graph checks. Its current JavaScript plugin API does not expose that graph. A plugin can rebuild one; our comparison includes that option. Basic cycles and import restrictions are existing capabilities. The useful addition is shared project facts for custom cross-file policies, consistent resolution and completeness handling.

Oxlint wins the cycle comparison in the final run. Native cycle samples range from 144.27 to 987.69 ms. The unchanged binary varied across runs; these results do not support a universal speed claim or attribution to a particular algorithm. Raw samples and load-average context are retained.

The reusable SDK query removed repeated file-lookup construction. The TypeScript graph median changed from 786.42 to 277.50 ms across the recorded runs. That is an observed end-to-end difference on this corpus, not an isolated operation benchmark.

At 4,000 files, an empty TypeScript subprocess adds 162.89 ms to the no-rule host median; the Rust executable adds 50.90 ms. These include JSON transfer, decoding and shutdown as well as runtime startup.

Measurements use fresh processes, warm filesystem caches, serial randomized trials, captured JSON and one Oxlint thread. Build time is excluded. The runner verifies identical input counts and detected violation sets before and during timing; mismatches have no timing ratio. The Oxlint custom graph plugin includes its independent TypeScript 5.9.3 parser and graph rebuild. It is a demonstration baseline, not a claim to be the fastest possible plugin.

Why support both Rust and TypeScript

Plugin languagesUseful propertyCost
Rust plugins onlyNative facts and fast common operationsRust expertise and a rebuild for static extensions
TypeScript plugins onlyFamiliar rule authoring for target teamsNode startup, JSON transfer and a smaller fact API than a compiler API
Both plugin languagesOne source analysis plus accessible project rulesVersioned protocol and compatibility tests

The CLI host stays in Rust in each option. Support both plugin languages. Built-in graph rules run in Rust; repository-specific rules can use TypeScript over the same immutable snapshot. Rust plugins can be static rules or separate executables. The implementation avoids an unstable Rust dynamic ABI and runs one subprocess per plugin per project. TypeScript rules can reuse createDependencyQuery(project) to build the file lookup once across many queried roots.

TypeScript 7 and Roslyn findings

TypeScript 7.0 is the native Go compiler; stable 7.0.2 was checked. The old compiler API is not shipped with that release, and 7.1 public API work remains experimental. Keep Effect semantic checks with the existing compiler integration until a stable provider is available.

Roslyn offers reusable immutable compilations, symbols, semantic models and project workspaces. Its useful design lesson here is shared project analysis consumed by many rules. Archguard does not inherit Roslyn type or data-flow guarantees.

Other tooling and license decisions

Research includes dependency-cruiser, Knip, ESLint boundaries, Sheriff, ast-grep, Tree-sitter, Biome, GritQL, ts-morph, ts-arch and Nx. Existing graph-policy tools remain credible alternatives and baselines. Core dependencies have checked permissive license choices; copied T3 reductions retain the MIT notice. Semgrep's maintained rules were not imported because their redistribution terms are separate and restrictive. MIT tRPC and Hono were assessed as possible future practice targets.
