# Research instructions

Keep experiments out of product dependencies and general user guides. Place adoption profiles under `examples/`; put historical reproductions, synthetic simulations, raw measurements, and experiment tools here. Root AGENTS.md also applies.

Record exact upstream commits. Distinguish full replay, reduced reproduction, and authored policy fixtures. A fixed revision that still triggers its claimed regression has not passed. Retain copied-source notices and verify fixture hashes/excerpts with the T3 history scripts before changing copied evidence.

Keep adoption candidates, historical migration policy, and experimental rules separate. Profile-entry counts are not historical bug counts. Module reachability does not prove execution. Installed-source checks preserve every failure and unsupported scheme; selected closures do not establish full repository coverage.

Build with `cargo build --release --locked --bins --examples` before measurement. Building examples alone does not refresh the CLI. Install only the pinned toolchain for the experiment. Reserve timing windows across agents; run builds, independent probes, validation, and timings separately.

Compare equivalent files and checks. Benchmark SDK traversal with both selected violations and clean controls. Record source revisions, corpus/configuration hashes, executable hashes, raw samples, full ranges, and unfavorable comparisons. Traverse product source recursively when hashing inputs.

Continuous cache-edit trials retain the last complete entry through incomplete edits. Keep them distinct from reset-primer trials. Reuse counts do not establish lower latency; retained cache measurements are slower than fresh analysis.

Preserve raw recorded JSON and archived HTML bytes during layout changes. Update active commands, evidence metadata, and fixture references; map old artifact paths in `relocations.json`. New trial output belongs in ignored `research/local/` until deliberately retained with its provenance.
